# Account-aware quota routing

`engine.accounts` is the immutable selector; `engine.account_collectors` adds an injectable boundary, not native authentication. Public API: `Binding(account: Account, pool_ref: str, credential_ref: str)`; `UsageReceipt(account_ref: str, pool_ref: str, provider: str, credential_ref: str, collected_at: datetime, payload: object)`; `collect_usage(account, resolver, fetcher, *, now) -> CollectionResult`. Resolver signature is `(account_ref, pool_ref, provider, credential_ref) -> Binding | None`; fetcher signature is `(binding) -> UsageReceipt`. Both callbacks exchange opaque references only; no token strings belong in references. Resolver/provider adapters are supplied by trusted runtime code. Their callbacks can have side effects: the module itself performs no I/O, credential refresh/store writes, activation, global token selection, requests, caching, spending, or reservation. An injected binding is not live identity attestation.

Binding and receipt must match exact account, pool, provider, credential and UTC collection time. Refusals have categorical `code` values and never include raw exception text/payload. A successful observation uses the receipt's `collected_at`, not a later clock read. Fetch failure/empty receipts are not observations and are never cached or converted to zero usage. Call `choose_account` only with successful `result.observation`; refusal carries no observation. Never substitute another same-provider account.

Codex parsing is closed: recognized plan types (`pro`, `prolite`, `team`, `business`, `enterprise`), exact boolean `allowed`/`limit_reached`, optional empty `additional_limits`; only windows with integer duration 18000/604800, numeric finite non-bool usage 0..100 and future integer UTC epoch reset are supported. Weekly-only 604800 is `weekly_only`; both durations are `session_and_weekly` regardless of field ordering. Missing, null primary, duplicate/unknown duration, unknown fields, non-empty additional limits, malformed/future windows fail closed. The Prolite weekly-only shape has no invented session window. Confirm plan type enumeration and wire schema against trusted provider documentation before expanding.

Anthropic accepts exactly `five_hour` and `seven_day` windows with finite numeric utilization 0..100 and future ISO-8601 UTC/offset `resets_at`; resulting times normalize to UTC. The only optional top-level field is `extra_usage`; documented `is_enabled`, `monthly_limit`, `used_credits` members are allowlisted, but enabled extra usage is refused. Unknown/model-specific limiting fields and missing/malformed windows refuse. Caller billing-lane evidence does not prove purchased credits will not be consumed; the final native adapter must independently establish this before execution.

Nous accepts numeric `subscription_remaining`, `subscription_allowance`, and optional `purchased_credits` (default 0); values must be finite nonnegative numbers, allowance positive and remaining <= allowance. Formatted text, total-usable balances, unknown fields and inconsistent values refuse. No raw balance authorizes spend: selector authorization, budget and reserve gates still apply.

Limitations: unsupported model windows refuse; shared refresh ownership and concurrency-safe reservations require native binding; callback trust/authentication remains pending. These APIs are not production identity guarantees and not deployed.
